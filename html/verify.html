Verify a notes export

A Solus Vires notes export can come with a verification file. This page checks it, entirely on your device: nothing you load here is sent anywhere, and the page keeps working with the internet switched off once it has loaded. What it can tell you is written out plainly below the results.

What a pass means. The server that runs this site held each piece of encrypted data, in exactly this form, at the times shown, and signed a statement saying so. It could not read the content then and cannot now. With the writer's PIN, the page also shows that the text in the export is what that encrypted data decrypts to. This is tamper-evidence. It is not a legal finding, and whether it matters in any proceeding is for a court to decide.

1. Load the verification file

Without the PIN, the page checks the signatures and fingerprints. With it, the page also decrypts each item here and compares it to the text in the file. The PIN never leaves this page.

2. Check the signing key

The file says it was signed with this key. Compare the key id with the one published at the key published on our page for advocates, or with a copy you obtained another way. A file that carries its own key proves nothing unless the key is the one the site publishes.

How it works

What is being checked, exactly

The statement

Each time a note, photo, profile or safety plan is saved, the server computes the SHA-256 fingerprint of the encrypted data it received and signs this text with an Ed25519 key:

solusvires-attest-v1|<kind>|<item id>|<sha256 of ciphertext>|<time>

The time is UTC in ISO 8601 form with a +00:00 offset. The page rebuilds that text from the file and checks the signature with the public key.

The fingerprint

The page hashes the encrypted data in the file and compares it to the fingerprint in the newest statement for that item. A match means the encrypted data is the data the server signed for. For a note, the hash is of the base64 text as stored; for a photo, of the decoded bytes.

The chain

An item that was edited, or re-encrypted when the writer changed their PIN, has more than one statement, each pointing at the one before. The page shows the first time the item was attested and every change since, with its reason. A chain that is broken or out of order is reported.

The text (with the PIN)

Notes are encrypted on the writer's device with a key derived from their PIN and a per-account salt (PBKDF2-SHA256, 600,000 rounds, AES-256-GCM). Given the PIN, the page derives the same key, decrypts each item, and compares it to the plaintext in the file. A match ties the readable text to the signed fingerprint.

This page does not need an account and sends nothing. Its source is served from this site like every other page, under a Content-Security-Policy that forbids third-party code. The verification file contains the writer's encrypted notes and, if they chose, the readable text; handle it as you would the printed export.
